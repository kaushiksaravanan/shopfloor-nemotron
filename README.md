# ShopFloor-Nemotron

> **RAG fails on Bharat manufacturing because Hinglish shop-floor idioms and BIS/HSN procedural reasoning live in weights, not retrieval. We close that gap with the first NeMo-trained Nemotron 3 Nano variant for SAP MSME manufacturing.**

A Nemotron 3 Nano 9B finetune that turns code-mixed Hinglish/Tamil shop-floor complaints
into BIS-cited, HSN-tagged, SAP-PM-ready Root-Cause-Analysis tickets — running fully
offline on a Jetson Orin Nano (8 GB).

---

## The Problem

Indian MSME shop floors generate millions of failure reports per year. They look like:

```
"Boss, CNC ka spindle phir se garam ho gaya — coolant line me air aa raha hai,
maintenance bola filter change karo but BIS 15879 ke hisab se HSN 8466
ke under warranty claim banega kya?"
```

Today this complaint never becomes a structured SAP-PM Notification because:

1. The plant supervisor speaks Hinglish/Tamil, not English.
2. The compliance reasoning (BIS standard X applies → HSN code Y → warranty path Z)
   requires *procedural* knowledge that does not live in any retrievable document.
3. The Jetson Orin Nano on the shop floor cannot run GPT-4o, and the plant has no
   reliable internet to call a cloud API.

## The Gap — Measured

We benchmark Llama-3.3-70B-Instruct (a frontier-class off-the-shelf model) against the
SHOPBench-IN 60-task seed[^baseline] and observe three reproducible failure modes:

| # | Failure                                       | Llama-3.3-70B accuracy | Why retrieval cannot save it           |
|---|-----------------------------------------------|------------------------|----------------------------------------|
| 1 | HSN 8-digit classification on Hinglish BOM    | 26.7 %                 | 8-digit code is a long-tail label; idioms ("garam ho gaya") lack a citable source. |
| 2 | BIS IS-number citation                        | 40.0 %                 | Requires multi-hop *procedural* reasoning over compliance rules. |
| 3 | Offline (no internet, ≤ 8 GB VRAM) deployment | 0 %                    | Model does not fit on Jetson Orin Nano. |

Overall accuracy on the 60-task seed: **66.7%** (RCA and SAP-PM schema validity hit 100%
because the schema task is easy for a 70B; the discriminating signals are the two knowledge
lookups above).

[^baseline]: Baseline measured 2026-07-01 against Llama-3.3-70B-Instruct on 60 SHOPBench-IN seed tasks via the Groq API (OpenAI-compatible endpoint, temperature=0, JSON response mode). Run ID: `runs/baseline-llama3.3-70b.json`. Note: original plan was Gemini-2.0-flash but vended Gemini free-tier keys were daily-quota-exhausted; we fell back to a frontier-class open-weight model so the baseline is fully reproducible by anyone with a free Groq account.

## The Recipe

A three-stage NVIDIA-native pipeline that targets all three failures at once:

1. **SFT (LoRA)** — NeMo AutoModel LoRA-tunes Nemotron 3 Nano 9B on 18 k synthetic
   complaint→ticket pairs generated by NeMo Data Designer and curated by NeMo Curator.
2. **GRPO** — NeMo RL runs GRPO against a custom FastAPI **NeMo Gym** environment
   that scores BIS citation correctness, HSN code validity, and SAP-PM schema match.
3. **NVFP4 quantization** — TensorRT-Model-Optimizer compresses the merged checkpoint
   to NVFP4, then TensorRT-LLM compiles it for the Jetson Orin Nano. NIM on A100 is
   the cloud fallback.

## SHOPBench-IN

A 1,200-example open benchmark spanning 6 plant types (CNC machining, injection
moulding, textile dyeing, food processing, pharma packaging, EV battery assembly)
× 4 languages (Hinglish, Tanglish, Kanglish, English) × 50 BIS standards.

Score = `0.4 · ticket_schema_F1 + 0.3 · BIS_citation_acc + 0.2 · HSN_acc + 0.1 · latency_under_2s`.

Baselines, evaluation harness, and leaderboard live under `bench/`.

| Cloud fallback   | NVIDIA NIM on A100                 | `serve/nim/`                 |
| Logging          | Weights & Biases                   | `train/wandb.yaml`           |
| Adapter hosting  | Hugging Face Hub                   | `train/hub.yaml`             |

## Reproduce

```bash
git clone https://github.com/sap-labs-india/shopfloor-nemotron.git
cd shopfloor-nemotron
make repro     # end-to-end: setup → data → SFT → RL → quant → eval
```

Run individual stages with `make gen-data`, `make train-sft`, `make train-rl`,
`make quant`, `make eval`, `make deploy-jetson`. See the `Makefile` for the full list.
